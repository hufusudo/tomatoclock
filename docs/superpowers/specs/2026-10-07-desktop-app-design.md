# TomatoClock 桌面版设计

- 日期：2026-10-07
- 状态：用户于 2026-10-07 审阅后回复“继续”，设计已批准，进入实施计划阶段
- 目标环境：用户的 CachyOS、KDE Plasma / Wayland 电脑，按本机架构打包
- 路径：architectural；本文件定义第一版边界，批准后再制定实施计划
- 依据：本次对话、现有网页设计、2026-10-07 已完成的提醒动画与测试

## 1. 目标与范围

把现有 TomatoClock 做成从电脑图标打开的自用桌面应用。用户设定工作时长，完成番茄后记录本次工作时长，长期保存每日番茄数和学习时长。离线使用，数据只在本机。

第一版交付：

1. 一个可点开的 Linux 桌面程序，单窗口；重复打开时聚焦已有窗口。
2. 现有工作/休息计时、暂停恢复、轮次、全屏提醒动画和较响提示音。
3. 今日完成番茄数、今日学习时长、全部历史累计学习时长。
4. “学习记录”视图：日期、番茄数、学习时长，按日期倒序排列；每页 30 天，可翻页。
5. SQLite 数据库持久保存记录和设置；升级应用不删除或重置数据。
6. 可选的一次性网页记录导入，详见第 6 节。导入默认只读取用户主动选择的文件。

后续版本再做折线图；本版先准备按日期查询的接口。托盘、后台常驻、开机启动、账号、云同步、任务清单、自动更新和其他操作系统打包均不纳入本版。

## 2. 已确认的运行与计时行为

- 关闭窗口即退出程序。未完成的工作段不计数、不计时，不在下次启动恢复；已保存的记录保留。
- 最小化窗口时程序仍运行，计时继续，到点发系统通知；切回后补放最新动画一次。
- 休息结束回到 READY，必须手动开始下一个番茄。
- 工作时长为 1–180 的整数分钟，仅 READY 可修改。短休 = 工作 ÷ 5，长休 = 工作 × 0.6，各 ±5 分钟微调，下限 1 分钟。每 4 个番茄进长休。
- 计时仍用 deadline 与当前时间相减；暂停不计入工作时长；唤醒后至多转换一个阶段，不产生连锁空转。
- 学习时长只累加已完成番茄的工作时长快照，休息、暂停、半截番茄均不计入。例如 25 分钟 + 50 分钟 = 2 个番茄、75 分钟。
- 每个番茄按其完成 deadline 所在的本地自然日入账，不拆分跨午夜番茄。完成后改设置不会改写旧记录。
- 轮次只在本次运行中保留，退出后重置；历史统计在数据库中保留。
- 手动修改系统时间仍是已知限制，不增加系统时钟管理。

## 3. 技术方案与模块边界

选择 Electron + SQLite，继续使用原生 HTML/CSS/JavaScript 界面。现有 timer.js 和 celebration.js 可复用；数据库由主进程管理，页面通过窄接口读写。桌面依赖仅用于运行和打包，不引入 UI 框架、外部字体或联网服务。

备选 Tauri + SQLite 需要新增 Rust 部分；本次优先复用现有 JavaScript 逻辑。PWA 的运行环境与后台行为仍由浏览器管理，本次选择独立桌面程序。

模块职责：

| 模块 | 职责 |
|---|---|
| desktop/main.cjs | 应用生命周期、单实例、窗口、原生通知、数据目录与数据库连接 |
| desktop/preload.cjs | 通过 contextBridge 暴露固定业务方法，不暴露 Node 或任意 SQL |
| desktop/database.cjs | SQLite 表结构、验证、参数化查询、事务、导入与按日统计 |
| js/timer.js | 现有纯计时状态机；仍不访问 DOM 或数据库 |
| js/celebration.js | 原有动画与声音，冻结 play/dismiss、五个依赖及 pending/幂等契约 |
| js/app.js + 桌面适配模块 | 事件接线、异步持久化、今日/累计数据、失败提示与重试 |
| 学习记录界面模块 | 每日记录分页展示，后续可消费同一接口绘制折线图 |
| 打包脚本与 package.json | 锁定运行依赖，产生可运行的 Linux 交付物 |

SQLite 驱动采用 better-sqlite3，通过 Electron 对应 ABI 的构建/重建流程使用。依赖版本在实施计划中锁定；先以真实 Electron 运行验证数据库模块，再进入界面集成，避免只在系统 Node 下通过测试却在成品中失败。

现有网页入口继续使用 localStorage 与浏览器通知，保持可运行；桌面入口使用 SQLite 与原生通知。共用计时和动画，不维护两套业务规则。

## 4. 数据文件与结构

数据库固定放在用户自有的数据目录：Linux 为 `${XDG_DATA_HOME:-~/.local/share}/tomatoclock/learning.sqlite`。与应用程序目录分离，替换程序不会覆盖数据。测试通过注入临时目录创建独立数据库，不触碰真实学习记录。

使用单个连接，SQLite 标准 DELETE journal 和事务；此数据量无需引入服务或复杂并发。数据库关闭后可完整复制 learning.sqlite 备份。通过 PRAGMA user_version 管理结构版本，第一版为 1；未来结构迁移在备份后事务执行，失败回滚，拒绝写入高于应用支持版本的数据库。

### completed_pomodoros：每个已完成番茄一行

| 字段 | 含义 |
|---|---|
| id TEXT PRIMARY KEY | 工作段开始时生成的 UUID，暂停恢复保留，防重复入账 |
| completed_at_ms INTEGER NOT NULL | 完成 deadline，Unix 毫秒 |
| local_day TEXT NOT NULL | 主进程按 completed_at_ms 生成的 YYYY-MM-DD |
| work_seconds INTEGER NOT NULL | 本段设定的工作时长快照，整数 60–10800 |

local_day 建索引。由主进程验证 UUID、有限整数时间和工作时长；不接受页面传入的 SQL 或任意文件路径。

### settings：设置

单行保存 workMin、shortAdj、longAdj，使用现有 sanitizeSettings 口径。仅 READY 修改；先保存成功再更新界面与计时器，写入失败保留旧设置并提示。

### imported_daily_totals：旧网页汇总

旧版只存日汇总，无法还原每个番茄，因此不伪造明细。表以 source + local_day 为主键，保存 pomodoros 与 work_seconds。

每日展示和历史累计由完成明细加导入汇总查询得到，不另外保存容易失配的每日计数表。未来折线图直接读取同一日汇总接口。

历史列表只列有完成或导入记录的日期。单日查询在无记录时返回 0 个番茄、0 秒；未来折线图按日期范围补齐零记录日，避免把缺失日期误画成连续学习。

## 5. 完成与保存链路

1. 用户开始工作段时生成 UUID，起跑时锁定工作时长快照。
2. 到点 tick 产生 work-done / break-started，延续现有休息规则。
3. 页面以 UUID、deadline、时长调用 saveCompletedPomodoro。主进程校验并在事务中插入。
4. UUID 已存在且内容一致时作为成功重试返回，不新增；内容冲突时返回错误。
5. 保存成功后刷新今日、累计和每日记录。系统通知与动画仍按阶段触发，不因保存失败取消休息提醒。
6. 保存失败时保留本次完成事件在内存待重试队列，显示“学习记录保存失败，请重试。”；统计只显示数据库已确认的数据，禁止开始新的工作段直至待保存记录成功。
7. 持久化待处理期间关闭窗口：等待当前操作完成。失败后如仍有未保存的已完成记录，提示重试保存、取消退出或明确放弃记录后退出；正常关闭不弹确认。

“退出丢弃未完成番茄”与“保护已完成但保存失败的记录”是不同情况。退出不恢复进行中计时，也不会将半截番茄入账。

固定桥接接口采用 Promise：读取设置、保存设置、保存完成记录、读取某日/全部累计、分页读取每日记录、导入旧日汇总、请求已知阶段的原生提醒。分页和日期范围由主进程校验，返回结构化成功/错误结果。另外提供只读窗口状态查询与订阅，订阅返回取消函数，供动画的五依赖适配使用。

## 6. 旧记录迁移

提供按需使用的一次性导入，迁移入口可在记录页找到。用户在网页主动导出 tomatoclock:v1 JSON，再在桌面版选择文件；不自动读取浏览器配置、Cookie 或资料目录。首次新建的桌面数据库从空记录开始，选择导入后才带入旧网页记录。

- 导入前展示日期范围、番茄数和总时长，用户确认后事务写入。
- 只接受合法日期、非负整数番茄数及非负整数秒数。损坏或非法文件整体拒绝，不部分写入。
- 固定来源标识 web-v1；同来源同日期重复导入替换旧汇总快照，不叠加；桌面完成明细始终保留。
- 导入不修改或删除网页数据。

## 7. 窗口、通知与界面

主窗口沿用极简计时布局，在页脚保留今日数字并增加历史累计。“学习记录”切换至简单表格，计时仍继续。记录页可一键回到计时，空记录显示“还没有完成的番茄”。

桌面系统通知由主进程发出，不依赖网页通知授权弹框；通知文案沿用当前版本。尽量减少到点提醒因窗口最小化被节流的延迟，窗口配置禁用 backgroundThrottling。

动画可播放状态由主进程计算：窗口显示、未最小化且已聚焦。主进程在 focus/blur、minimize/restore、show/hide 时通知页面。页面缓存此状态，用作 celebration 的 isVisible/watchVisibility 依赖；不依赖关闭节流后可能保持 visible 的 document.visibilityState。不可播放时只记最新 pending，切回恰好一次。

保留全屏演出、较响钟声、点击/Esc 关闭、减少动态效果和关闭后资源清理。窗口关闭即退出全部计时和提醒，不做托盘。

只加载随程序打包的本地页面。开启 contextIsolation 和 sandbox，关闭 nodeIntegration；预加载仅暴露上述业务接口，校验 IPC 来源。禁止任意页面导航、弹新外部窗口和远程内容加载，设置与当前内联动画样式兼容的 CSP。

## 8. 错误与恢复

| 情况 | 行为 |
|---|---|
| 数据目录或数据库无法打开 | 显示清楚错误，不创建替代空库，不允许开始新的工作段 |
| 数据库损坏或结构版本过高 | 保留原文件，停止写入，不自动清空或降级 |
| 完成记录保存失败 | 依第 5 节保留待重试事件，明确展示尚未保存 |
| 设置保存失败 | 保留旧设置，提示失败 |
| 系统通知不可用或系统勿扰 | 页面和声音提醒继续可用；不修改系统通知设置 |
| 休眠后唤醒 | 补记至多一格，以 deadline 入账；不在休眠中凭空连续学习 |
| 渲染进程意外退出 | 结束本次未完成工作段；已提交数据库记录保留 |

## 9. 交付和维护

第一版交付本机架构的 Linux 便携应用目录、可执行启动器、应用图标和安装到用户应用菜单的脚本。应用程序与数据库分开，用户更新程序无需清空记录。首次安装脚本只创建本应用自己的文件，不编辑 KDE、shell、/etc、服务、内核或 btrfs 配置。

只在项目内安装开发依赖；优先使用预编译二进制和可写临时缓存。工具无法重定向的必要用户缓存写入须通过沙箱权限审查，不重定位 HOME 或编辑用户配置。若验证中确实缺少系统级编译依赖，先说明具体包、用途和影响，并按用户 AGENTS 要求发出强烈警告、取得明确确认后才安装。不进行系统更新、驱动调整或沙箱配置修改来凑运行环境。

自动更新不做。依赖锁定版本，后续升级需跑回归；数据库结构更新前备份和迁移。折线图后续从每日查询接口添加，不改已有记录的统计口径。

## 10. 验收

- 已有 31 条计时/存储/动画用例继续通过，网页入口不回归。
- 在真实 Electron 及最终打包产物中读写实际 SQLite 文件，验证关闭重开后的记录与设置。
- 同日先完成 25 分钟、再完成 50 分钟：2 个番茄、4500 秒；历史累计同口径。
- 完成记录重复提交、保存失败后重试：均只入账一次；内容冲突明确报错。
- 跨午夜、三个时区、过去日期、零记录日、历史分页和升级后旧数据验证。
- 关闭中途工作段后重开：未完成段不入账，已完成记录仍在。
- 最小化期间到点，休眠后唤醒、休息结束手动开工、动画恰好一次。
- 验证数据库写失败、非法导入、重复导入、设置失败与退出时未保存记录处理。
- 在用户 CachyOS / KDE Wayland 上实际点开程序、检查通知和声音；无图形环境下的检查不能替代此项。
- 禁止靠关闭 Electron 沙箱或修改底层系统配置通过验收。
