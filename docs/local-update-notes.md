# 本地启动更新维护记录

用户批准：本机自用，启动时检查新版，点击一次更新；没有网络发布、运行中热替换、托盘或自动定时检查需求。沿用已有启动/安装流程与当前 `codex/desktop-app` 分支。

## 流程与边界

- `npm run release:local`：先构建 Linux x64 包，再运行完整测试，通过后写不可变更新快照和 `dist/updates/latest.json`。相同版本号但内容变更仍可更新，低版本号不提示。
- `desktop/releases.cjs`：文件路径、大小、权限、SHA-256 清单；拒绝链接、特殊文件与路径越界；复制后重新校验，更新源变化不安装；清单与发布标识匹配。
- `scripts/install-user.cjs`：安装为 `versions/<SHA256>/package`，固定启动入口与原子 `current` 链接；保存更新源绝对路径；原平铺安装保留，用户额外文件保留。启动恢复使用 `.bootstrap/runtime` 固定指向已验证的安装版本，不依赖新 `current` 中的可执行文件。
- `desktop/application.cjs`：设置隔离配置目录、获得单实例锁、等待 Electron 就绪后执行更新钩子；更新发生在打开数据库和计时窗口之前。已有实例时不更新，只唤起窗口。
- `desktop/local-update.cjs`：原生“立即更新 / 暂时跳过”；先准备完整程序，备份数据库，再记录更新事务并切换。安装/校验失败继续当前版；新窗口加载且数据库正常才确认首次启动成功。失败更新暂时屏蔽其内容标识。
- `desktop/launch-bootstrap.cjs`：新程序启动前即异常退出时，固定恢复入口校验并切回上一版，避免新入口语法错误/二进制损坏使恢复代码也无法运行。
- 更新前发现 SQLite `-journal` 或 `-wal` 时暂缓更新，让当前版先恢复数据库，避免仅复制主文件产生不一致备份。数据库备份不覆盖既有备份，重试生成独立文件。
- 程序切回不会覆盖数据库。未来数据库结构升级必须明确迁移和旧版兼容方案；已有备份用于人工维护恢复，不自动丢弃升级后的新学习记录。
- 0.3.1 接续：用户要求每次更新清理生成物、方便 AI 维护，并明确选择保留全部数据库备份。成功启动后保留当前版、上一版及固定恢复运行时；更新源保留当前与上一份发布。其他文件和数据不参与清理。本机 btrfs 文件复制请求 reflink，未调用任何文件系统管理命令或修改系统配置。
- 移动/删除源码与更新源不会影响当前程序正常使用，后续更新需重新配置更新路径。完整运行时更新和固定 bootstrap 自身升级仍可通过维护安装脚本进行。

## 清理与维护接续（0.3.1）

`desktop/cleanup.cjs` 只操作安装 `versions` 和更新源 `releases`。删除前必须有有效清单、内容校验完全一致、没有额外用户文件、没有链接；无法确认的目录跳过。保留集合从当前链接、上一版状态与固定运行时链接读取，任何保护入口异常则停止清理。更新事务仍在时跳过安装清理；清理错误不让成功的新窗口退回旧版。

独立审阅发现发布/复制完成至状态提交之间的并发窗口，已用 `maintenance-lock.cjs` 协调：发布覆盖生成→latest 提交，安装覆盖复制→备份→pending→切换，清理使用相同目录锁。活跃或未知归属的维护锁暂缓，确定所属进程退出的旧锁排他回收。测试强制插入并发清理，确认新版不会被提前删除。额外空目录也使旧包不再符合清理条件；只读检查当前用户运行中的程序版本并加入保留集合，避免多次手动安装时误删仍运行的旧程序。

生成复制目录新增 `.stage-owner.json`：归属本应用且 PID 已退出才清理，活跃任务和没有标记的临时目录保留。正常生成完成后移除该标记，失败时仍由构建过程自身清理。

`scripts/cleanup.cjs` 默认只预览，`--apply` 才执行；先验证安装和更新源两处，再处理候选。`npm run cleanup:preview` 与 `npm run cleanup` 是固定维护入口。清理脚本没有数据库目录参数，不读写学习数据库或备份。

仓库根新增精简 `AGENTS.md`，`HANDOFF.md` 改为当前状态和代码地图；历史文档保留供有需要时查阅，旧交接内容仍可从 Git 历史读取。没有删除历史设计、依赖框架或用户手工文件；避免给每次维护增加重复文档。
