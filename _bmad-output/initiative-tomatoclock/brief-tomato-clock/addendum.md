# Addendum — TomatoClock 番茄钟

补充材料：不属于 brief 正文、但对后续（PRD / 架构 / 实现）有价值的内容。按来源分类。

## 外部研究速览（2026-10-06 侦察）

**番茄工作法本体（Wikipedia / Cirillo 原版）**
- 标准节奏：25 分钟专注 + 5–10 分钟短休；每 4 个番茄后 20–30 分钟长休
- 番茄不可分割：中途被打断则该番茄作废（或记录后推迟）——本项目"关闭即作废"规则的出处
- 原版强调"规划 → 记录 → 复盘"（To Do Today 列表）——v1 只取"记录"，规划（任务清单）明确延后
- 2025 年 scoping review：时间结构化休息在减缓精神疲劳、维持持续专注上优于自主休息

**同类网页产品**
- Pomofocus：可自定义时长、桌面/移动浏览器、任务列表、统计——最接近的标准答案
- Pomodoro Tracker：TODO + 统计 + 账号登录 + 多语言
- Flowmodoro：反番茄流派（先干活、累了按需歇），证明固定节奏并非唯一范式；v1 不采用

## 被否决的备选与理由

| 备选 | 结论 | 理由 |
|---|---|---|
| Web Push（关掉标签页仍能提醒） | ❌ v1 不做 | 需 Service Worker + 推送服务端，复杂度与自用工具不匹配；明确写入 Scope"不做" |
| 半截番茄计入总时长（B 方案） | ❌ 选 A（作废） | 番茄不可分割原则；口径可一句说完（总时长 = 已完成数 × 工作时长） |
| 长休固定 20 分钟（B 方案） | ❌ 选 A（× 0.6） | 与短休同一套比例逻辑，风格统一 |
| 休息时长完全锁死不许改 | ❌ 选 ±5 分钟微调 | 用户需要活口，但 ±5 堵死"借微调取消休息" |
| Flowmodoro 式自由节奏 | ❌ 不采用 | 用户明确要"推算式"而非"自由式" |
| 强制锁页 / 到点锁定 | ❌ 不做 | 与"工具只负责叫，起床是你的事"的越界纪律冲突 |

## 到点行为链——完整场景推演（供实现参考）

1. **到点，用户在别的标签页（常态）** → Notification API 弹系统通知"专注结束，该短休了"；页面内记录"提醒未处理"。
2. **用户切回页面，提醒未处理** → 补放小动画 + 提示音一次；处理（点掉）后不再打扰。
3. **用户无视** → 番茄照常计数，不暂停、不惩罚。
4. **电脑睡眠 / 中午离开** → 计时基于"开始时刻倒推"，真实时间照走；唤醒后若已到点，按规则 1 补发通知（补休不自动补偿）。
5. **标签页彻底关闭** → 计时终止，无提醒（已知边界）。
6. **关闭时有进行中的番茄** → 作废，不计数不计时。

## 技术约束与实现提示（下游架构参考）

- **计时精度**：浏览器会节流后台标签页的 setInterval；必须用时间戳差值倒推剩余时间，tick 只负责刷新显示
- **通知权限**：Notification API 需用户手势触发一次授权；拒绝则退回页面内动画+声音（降级路径要测）
- **持久化**：localStorage 按自然日分组（本地时区），存 `{date: {pomodoros: n, studySeconds: n, settings...}}`；跨午夜写入新键
- **提醒音**：后台标签页中 AudioContext 可能被挂起，切回页面恢复时需补放（与场景 2 合并处理）
- **零依赖优先**：单页静态应用即可满足全部 v1 需求，无需框架/构建亦可（实现自由度留给实现阶段）

## 使用场景事实（用户自述，写 brief 时的依据）

- 专注期间主要在用 AI（对话框是主工作面），基本不停留在番茄钟页面
- 中午休息会关闭番茄钟，下午再打开——持久化必须跨关闭
- 自评"平常就是这样的"：标准算法（÷5 / ×0.6）与其日常疲劳节奏吻合
